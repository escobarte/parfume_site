# Импорт каталога из CSV — инструкция

Три файла решают три разные задачи. Формат определяется автоматически по строке заголовка — переименовывать файлы не нужно. Фото — отдельным ZIP-архивом, см. «Фото товаров» ниже.

| Задача | Шаблон | Заголовок |
|---|---|---|
| Загрузить/обновить товары (описание в одну локаль) | `import-template.csv` | `handle,title,brand,…,volume,sku,price` |
| Загрузить/обновить товары с описанием на трёх языках и фото за один прогон | `import-template-multilang.csv` | `handle,title,brand,…,description_ro,description_ru,description_en,images,…` |
| Обновить только цены и остатки | `import-template-prices.csv` | `sku,price,stock` |
| Добавить перевод описания точечно | `import-template-translations.csv` | `handle,locale,description` |

## Как запускается

```bash
pnpm run import docs/import-template.csv --dry-run   # проверка без записи
pnpm run import docs/import-template.csv             # боевой импорт
pnpm run import docs/import-template.csv --locale=ru # писать контент в русскую локаль
```

Именно `pnpm run import`, а не `pnpm import`: `import` — это ещё и собственная команда pnpm (перенос lock-файла из другого пакетного менеджера), она перехватывает вызов и скрипт проекта не запускается вовсе (`ERR_PNPM_LOCKFILE_NOT_FOUND` или `Unknown option: 'dry-run'`). Есть и однозначный алиас — `pnpm import:csv <файл>`.

CLI умеет то же, что и форма `/admin/catalog-import`, **кроме загрузки ZIP с фото** — архив грузится только через форму в браузере (нужен админ-доступ и живой Next-запрос), у CLI для этого нет команды.

**Всегда начинайте с `--dry-run`.** Он читает файл целиком, показывает все ошибки с номерами строк (как в Excel) и говорит, что будет создано и что обновлено. В базу при этом ничего не пишется.

Боевой импорт идёт **одной транзакцией**: если хоть одна строка не проходит проверку, не применяется ни одна. Повторный импорт того же файла не создаёт дублей — товары обновляются по `handle`, варианты по `sku`. **Исключение — колонка `volume`** (см. ниже): значение не из списка 5 не блокирует весь файл, пропускается только этот вариант, с предупреждением в отчёте.

**После импорта на проде каталог (`/catalog`) может ещё какое-то время показывать старую (в т.ч. пустую) выдачу**, хотя главная страница и карточка товара уже видят новые данные. Причина — CLI (`scripts/import.ts`) идёт отдельным от Next.js процессом, а инвалидация кэша витрины (`revalidateTag`) работает только изнутри живого запроса — CLI её физически не может позвать (тихо гасится, это ожидаемо). Есть 300-секундная страховка по времени (`CACHE_TTL`, `src/lib/cache.ts`), но на практике она не всегда обновляет `/catalog` сама по себе быстро. **Самый надёжный и быстрый фикс — зайти в `/admin`, открыть любой товар и нажать «Сохранить» (даже без изменений)** — это настоящий запрос внутри Next.js, хук коллекции сам сбросит кэш сайта целиком, `/catalog` обновится сразу же. Ничего в БД пересохранять/чинить не нужно — данные после импорта уже корректны, дело только в кэше.

## Колонки товарного файла (формат A)

Одна строка = **один объём (вариант)**. Строки одного товара склеиваются по `handle` — данные товара (название, бренд, описание) достаточно заполнить в первой строке, но проще продублировать во всех.

| Колонка | Обяз. | Что это |
|---|---|---|
| `handle` | да | Ваш внутренний ключ товара. По нему идёт обновление при следующих загрузках. Не меняйте его для уже загруженных товаров. |
| `title` | да | Название товара — общее, одно на все локали (обычно на английском). Значение из `--locale` на него не влияет. |
| `brand` | да | Slug бренда латиницей: `maison-orphee`. Нет такого — будет создан автоматически. |
| `brand_logo` | нет | Логотип бренда — **одно** имя файла из медиатеки: `maison-orphee.svg`, без `\|` и без ссылок. Файл должен быть загружен заранее тем же ZIP-архивом, что и `images`. Единственная колонка товарного файла, которая пишет **не в товар, а в запись бренда** — отсюда её особенности: ячейку достаточно заполнить в одной строке бренда (у бренда с 40 товарами повторять её 40 раз не нужно, но и не вредно), запись бренда обновляется один раз за прогон. Если строки одного бренда указывают **разные** файлы — берётся первый, остальные в отчёт. Непустая ячейка заменяет уже загруженный логотип (CSV — источник истины); пустая не трогает. Имя не найдено — не ошибка формата: предупреждение в отчёте, логотип остаётся прежним. Логотип виден на странице `/brands`; бренд без логотипа показывается там названием текстом. |
| `country_of_origin` | нет | Страна-производитель — ровно одно из трёх значений: `uae`, `europe`, `usa` (регистр и лишние пробелы не важны, русские подписи «ОАЭ»/«Европа»/«США» **не** принимаются — канон один, как у `volume`). Страна относится к товару, а строк на товар несколько: берётся значение **первой строки** этого `handle`; если строки одного товара указывают разные страны — в отчёт уходит предупреждение, применяется первая. Пустая ячейка ничего не меняет: у уже существующего товара остаётся его страна, у нового срабатывает значение по умолчанию (`europe`). Значение не из списка — не ошибка формата: предупреждение в отчёте, товар импортируется, поле не трогается. |
| `product_category` | нет | Раздел каталога — ровно одно из трёх значений: `perfume`, `bodyCare`, `lipBalm` (регистр и лишние пробелы по краям не важны, русские подписи «Парфюмерия»/«Уход за телом»/«Бальзам для губ» **не** принимаются — канон один, как у `volume` и `country_of_origin`). Это **не** «Кому» и не `categories` ниже: поле решает, в какой раздел левой навигации попадёт товар — `bodyCare` → «Body Care», `lipBalm` → «Lip balm», `perfume` → «For Her» / «For Him» по колонке `gender` (`unisex` — только в общем каталоге). Исключение — `gender = kids`: такой товар виден в «Kids» при любом `product_category`, а уход за телом / бальзам с `kids` — одновременно и в «Body Care» / «Lip balm». Раздел относится к товару, а строк на товар несколько: берётся значение **первой строки** этого `handle`; если строки одного товара указывают разные разделы — в отчёт уходит предупреждение, применяется первая. Пустая ячейка ничего не меняет: у уже существующего товара остаётся его раздел, у нового срабатывает значение по умолчанию (`perfume`). Значение не из списка — не ошибка формата: предупреждение в отчёте, товар импортируется, поле не трогается. |
| `categories` | нет | Slug-и через `\|` или запятую: `femei\|seturi`. Это таксономия (коллекция «Категории»), не путать с `product_category` выше. |
| `gender` | нет | `female` / `male` / `unisex` / `kids`. Регистр строгий: `Kids` или `KIDS` дают ошибку формата, и файл не импортируется целиком. Пробелы по краям ячейки не ошибка — их, как и во всех колонках, срезает сам разбор CSV (`kids ` читается как `kids`). Товар с `kids` попадает в раздел «Kids» при любом `product_category`. |
| `family_ro`, `family_ru`, `family_en` | нет | Семейство/группа аромата — свободный текст на трёх языках (ПРОМПТ 12 v2, раньше был фиксированный список `floral/woody/…`, теперь просто короткая фраза). Каждая колонка пишется в свою локаль, пустая — не трогает уже сохранённое значение. |
| `notes` | нет | Slug-и нот через `\|`: `bergamota\|santal`. Плоский список — по нему работают фильтры. Незнакомый slug — не ошибка: автоматически заводится заготовка ноты (`needsReview: true`, временное название = сам slug на всех трёх языках) — см. «Словарь нот» ниже. |
| `notes_top`, `notes_heart`, `notes_base` | нет | Пирамида нот для страницы товара — те же slug-и, та же логика авто-создания заготовок. |
| `images` | нет | Имена файлов из медиатеки через `\|`: `alpha-1.jpg\|alpha-2.jpg`. Порядок в ячейке = порядок фото в галерее товара, первое — обложка карточки. Файлы должны быть загружены заранее ZIP-архивом на том же экране — см. раздел «Фото товаров» ниже. Непустая ячейка полностью заменяет уже привязанные фото (CSV — источник истины); пустая ячейка существующие фото не трогает. |
| `variant_image` | нет | Фото под реальный размер **этого объёма** (3ml — своё фото, 5ml — своё). Одно имя файла из медиатеки: `atomizer-5ml.png`, без `\|` и без ссылок — файл должен быть загружен заранее тем же ZIP-архивом, что и `images`. При выборе этого объёма на странице товара оно заменяет главное фото; у варианта без своего фото показывается первое фото товара из `images`. Одно и то же имя можно указывать у разных товаров (атомайзер физически один). Пустая ячейка не трогает уже привязанное фото. Имя не найдено — не ошибка формата: вариант остаётся без своего фото, а имя попадает в раздел отчёта «Фото вариантов: не найдено» с указанием товара и объёма. |
| `description` | нет | Текст описания одной строкой. Попадает **сразу во все три языка**, но только туда, где описание пока пустое — готовые переводы не затираются. Игнорируется, если в файле есть хоть одна из колонок ниже. |
| `description_ro`, `description_ru`, `description_en` | нет | Описание сразу на трёх языках **за один прогон** — каждая колонка пишется в свою локаль, независимо от `--locale`. Пустая ячейка одной из локалей просто пропускается и не затирает уже сохранённый перевод в базе — заполните только те языки, которые реально изменились. |
| `is_new`, `is_hit` | нет | `1` / `0` (можно `да`/`yes`/`true`). |
| `volume` | да | Объём — ровно одно из 5 значений: `3ml`, `5ml`, `10ml`, `Travel Size`, `Full Size` (та же формулировка, что в select `/admin`). Значение не из списка — **не ошибка формата**: эта строка (вариант) пропускается с предупреждением в отчёте, остальной файл, включая другие варианты того же товара, загружается как обычно. Если у товара **все** его строки оказались с плохим объёмом — товар целиком не создаётся (нужен хотя бы один валидный вариант), тоже с явной пометкой в отчёте. |
| `sku` | да | Артикул варианта. Должен быть уникальным по всему файлу. |
| `price` | да | Цена в MDL. Дробная часть — запятая или точка. |
| `old_price` | нет | Цена до скидки, MDL — та, что показывается зачёркнутой. **Пустая ячейка (или отсутствие колонки) не трогает уже сохранённую уценку** — как у `images`, `country_of_origin` и `variant_image`. До 2026-09-12 было наоборот: перезаливка прайса без этой колонки молча снимала зачёркнутые цены со всех товаров. Чтобы **снять** уценку, через CSV способа нет — только вручную в `/admin` у нужного товара. ⚠️ Если новая цена оказывается ВЫШЕ сохранённой `old_price` не у всех вариантов товара, а лишь у части, импорт всего файла упадёт: действует правило «скидка на всех активных вариантах сразу или ни на одном». Лечится тем, что в такой строке `old_price` заполняется явно (или уценка снимается в `/admin`). |
| `stock` | нет | Остаток, штук. Пусто = 0. |
| `is_active` | нет | `0` скрывает вариант с витрины. Пусто = показывать. |

### Формат B — варианты одной колонкой

Если ваша система выгружает варианты JSON-ом, вместо колонок `volume/sku/price/…` используйте одну колонку `variants`:

```
handle,title,brand,variants
MO-EXEMPLU-01,Exemplu Lemn,maison-orphee,"[{""volume"":""5ml"",""sku"":""MO-EX1-05"",""price"":240,""stock"":12,""image"":""atomizer-5ml.png""}]"
```

Внутри JSON кавычки удваиваются — так Excel сохраняет их сам.

Необязательное поле `image` внутри варианта — полный аналог колонки
`variant_image` формата A (одно имя файла из медиатеки, те же правила и тот же
раздел отчёта). Остальные колонки товара, включая `country_of_origin`, `product_category` и
`brand_logo`, в формате B работают ровно так же, как в A.

### Описания: одна колонка или три

Есть два варианта, и файл сам решает, какой из них применяется — по заголовку.

**Вариант 1 — одна колонка `description` (когда переводов ещё нет).** Текст пишется **сразу во все три языка** одним прогоном. Это осознанное дублирование: пустое описание на румынской или английской версии сайта выглядит как недоделанный сайт, а дубль хотя бы читается и сразу видно, что его надо перевести.

Важное ограничение — **дубль ложится только туда, где описание пустое**. Если у товара уже есть нормальный румынский и русский текст, а приезжает прайс с одной колонкой, эти переводы останутся нетронутыми, заполнится только пустой язык. Один неаккуратный импорт прайса не может стереть переводческую работу.

Отчёт в таком файле показывает заметное предупреждение (и в проверке, и в боевом прогоне):

```
⚠ В файле одна колонка description — этот текст продублирован на все языки,
  где описание было пустым (3 шт).
  Готовые переводы не тронуты. Дубли нужно перевести вручную в админке —
  сейчас там один и тот же текст на разных языках.
```

Если предупреждения нет — значит дублировать было некуда, во всех языках уже есть текст.

**Вариант 2 — три колонки `description_ro`, `description_ru`, `description_en` (когда переводы готовы).** Каждая уходит в свой язык за один прогон, дублирование не применяется:

```
handle,title,brand,volume,sku,price,description_ro,description_ru,description_en
MO-EXEMPLU-01,Wood Example,maison-orphee,5ml,MO-EX1-05,240,"Lemn cald și bergamotă limpede.","Тёплое дерево и прозрачный бергамот.","Warm wood and clear bergamot."
```

Пустая ячейка одной из локалей просто пропускается и не затирает уже сохранённый перевод — заполните только те языки, которые реально изменились.

Первая строка отчёта говорит, какой вариант распознан: `(описания: ro, ru, en)` — файл трёхколоночный; `(описание: одна колонка на все языки)` — одноколоночный. Если ждали первое, а видите второе — проверьте точное написание заголовков `description_ro/ru/en`.

`title` в обоих вариантах один и тот же на все языки (см. выше — он общий, не переводится). Селектор «Локаль контента» на описания не влияет ни в одном из вариантов — он остался только для названий брендов, категорий и нот, которые импорт заводит автоматически при первой встрече.

## Фото товаров — архивом, без внешних ссылок

Путь для клиента, у которого фото лежат локально (не выложены никуда в интернет): запаковать папку → загрузить архив на экране `/admin/catalog-import` → в CSV указать те же имена файлов в колонке `images`. Два отдельных действия одно за другим, не одна кнопка:

1. **Собрать архив.** Один ZIP, файлы можно как в корне архива, так и по подпапкам — подпапки игнорируются, учитывается только имя файла. Просите у клиента **квадратные фото ~1200×1200 px, до 1 МБ каждое** — этого достаточно для всех размеров, которые генерирует витрина (превью в админке, карточка листинга, галерея товара), и они точно проходят под лимит.
2. **Загрузить архив** — блок «Шаг 1» на `/admin/catalog-import`, отдельная кнопка «Загрузить архив». Лимиты: до 200 МБ на архив, до 8 МБ на отдельный файл — если что-то больше, файл пропускается с пометкой в отчёте, весь архив при этом не отклоняется. Принимаются только `jpg`/`jpeg`/`png`/`webp`; всё остальное (PDF, TIFF, `.DS_Store` и т.п.) — тоже пропускается с пометкой, не ошибка. Файл с именем, которое уже есть в медиатеке, не дублируется — привязка в CSV сработает на существующий.
3. **⚠ Имя файла в архиве и имя файла в колонке `images` должны совпадать до буквы**, включая регистр и расширение (`Alpha-1.JPG` ≠ `alpha-1.jpg`). Опечатка — не ошибка формата: строка с ней в отчёте попадёт в раздел «Фото: не найдено», товар при этом импортируется без этого конкретного фото, весь прайс не откатывается.
4. **Загрузить CSV** — блок «Шаг 2», колонка `images` (см. таблицу выше). Отчёт dry-run и боевого прогона одинаково показывает строку `Фото: привязано N, не найдено M` со списком строк и имён, которые не нашлись — прогоняйте dry-run и проверяйте эту строку до боевого импорта, как и с остальными полями.
5. **Фото под конкретный объём** — та же схема, колонка `variant_image` (одно имя файла на строку-вариант). В отчёте у них свой раздел — `Фото вариантов: привязано N, не найдено M`, где каждая ненайденная запись подписана товаром и объёмом (`MO-EXEMPLU-01 · 5ml`), чтобы сразу видеть, какой именно вариант остался с общим фото товара.

## Словарь нот — отдельный ZIP+CSV импорт (ПРОМПТ 12 v2)

У нот (ароматических ингредиентов — не путать с товарами) свой отдельный экран
`/admin/notes-import`, вне каталог-импорта: словарь нот наполняется партиями по
мере готовности новых иконок от дизайнера, независимо от прайса товаров.

1. **Шаг 1 — иконки, тот же архив, что и у фото товаров.** Тот же блок «ZIP-архив»,
   что на `/admin/catalog-import` (переиспользуется как есть — `/api/media-import`
   ничего не знает про товары или ноты, просто кладёт файлы в общую медиатеку по
   имени файла). Имя файла = `slug` ноты: `amber.png`, `patchouli.jpg`.
2. **Шаг 2 — CSV со словарём**, колонки: `slug,title,group,image`.
   - `slug` — обязателен, латиницей, тот же slug, что и в CSV товаров (`notes`/
     `notes_top`/`notes_heart`/`notes_base`).
   - `title` — название ноты **на английском** (решение владельца, ПРОМПТ 13:
     названия/описания нот больше не переводятся, одно значение видно на всех
     трёх локалях сайта сразу). Обязателен для новой ноты; при обновлении уже
     существующей можно оставить пустым — не затрёт сохранённое название.
     Старый формат из трёх колонок (`name_ro`/`name_ru`/`name_en`) больше не
     поддерживается — файл в старом формате отклоняется отдельной ошибкой.
   - `group` — свободный текст (не список), например `citrus`/`woods-resin-base`/
     `amber-molecules` — своя группировка дизайнера, не привязана к фиксированному
     набору.
   - `image` — точное имя файла из ZIP-архива шага 1 (как колонка `images` у
     товаров) — регистр и расширение должны совпадать. Пустая ячейка — нота без
     иконки, в пирамиде на странице товара покажется плейсхолдер.
   - Незнакомый `slug` — создаёт новую ноту-заготовку с `needsReview: true`.
     Известный `slug` — обновляет только те поля, что заполнены в строке; сам
     флаг `needsReview` при этом импортом не трогается — снимается только вручную
     в самой карточке ноты (`/admin/collections/notes`), когда название и иконка
     готовы.
3. Строка с ошибкой (пустой `slug`, ненайденная иконка) не откатывает весь файл —
   это отдельный отчёт по строкам (успех/предупреждение/ошибка), не транзакция
   «всё или ничего», как у товарного CSV: словарь нот наполняется партиями от
   разных дизайнеров, одна опечатка не должна блокировать остальные 149 строк.

## Важные правила

- **Цены только в MDL**, без символа валюты и без пробелов-разделителей тысяч.
- Slug-и пишутся **латиницей строчными буквами через дефис**. Кириллица и диакритики приводятся к латинице автоматически, но лучше писать сразу правильно.
- Если в отчёте dry-run в разделе «Справочники будут созданы автоматически» появились неожиданные бренды или ноты — почти наверняка это **опечатка в slug**. Исправьте файл и прогоните dry-run ещё раз.
- Товары, которых нет в файле, не удаляются и не скрываются — импорт ничего не стирает.
- Варианты, которых нет в файле, у существующего товара тоже сохраняются. Чтобы убрать вариант с витрины, поставьте ему `is_active = 0`.
- Файл сохраняйте в **CSV UTF-8**. Разделитель — запятая или точка с запятой, определяется автоматически.
