**Документ-исполнитель.** Стратегия и обоснования — в ТЗ (`roadmap-parfum-catalog.md`). Этот файл кладётся в репозиторий как `docs/PLAN.md`, рядом в корень — `CLAUDE.md`. Claude Code работает по нему шаг за шагом.

**Отличия от ТЗ (зафиксировано для Молдовы):** три локали RO/RU/EN (RO — дефолт), валюта MDL, аналитика GA4 (Яндекс.Метрика — опционально по желанию клиента), домен предположительно `.md`.

## 0. Как работает этот план

### Роли
- **[CC]** — делает Claude Code: пишет код, конфиги, документы, гоняет локальные команды.
- **[ТЫ]** — делаешь ты: git, все действия на сервере, покупки/регистрации, проверки по чек-листам.

### Жёсткие правила (продублированы в CLAUDE.md)
1. **Git — только ты.** Claude Code не выполняет ни одной git-команды. После каждого шага он предлагает точку коммита: список файлов + готовое сообщение. Помечено значком **⎇**.
2. **Сервер — только ты.** У Claude Code нет SSH. Все серверные команды он выдаёт текстом, ты вставляешь их в свою SSH-сессию.
3. **Чек-лист после каждого шага.** Claude Code завершает шаг мини-чек-листом (помечен **✔**) — конкретные команды/URL и ожидаемый результат. Не прошёл чек-лист → шаг не закрыт, к следующему не переходим.
4. **Секреты.** Claude Code редактирует только `.env.example`. Реальный `.env` заполняешь ты.

### Рабочий цикл
Готовые промпты по фазам — в `docs/PROMPTS.md`, это главный рабочий файл. Данный PLAN.md — спецификация «что строим»: Claude Code читает его сам. Метки [ТЫ] в шагах ниже описывают минимум, который физически нельзя автоматизировать (аккаунты, оплаты, git-вставка); актуальное распределение работ задают PROMPTS.md и CLAUDE.md — всё проверяемое командой Claude Code проверяет сам и ведёт `docs/CHANGELOG.md` после каждого шага.

### Границы этапов
- **Фазы 0–8 — полностью локально** (WSL, Docker, localhost). Продакшена не существует.
- **Фазы 9–11 — перенос на платформу**: домен, сервер, Cloudflare, деплой, запуск.

## 1. Зафиксированные решения

| Область | Решение |
|---|---|
| Стек | Next.js 15 (App Router) + Payload CMS 3 + PostgreSQL 17, TypeScript strict, pnpm, Node 22 LTS |
| UI | Tailwind CSS v4 + shadcn/ui; до получения макетов — нейтральная тема на дизайн-токенах |
| Локали | `ro` (дефолт), `ru`, `en` через next-intl; префикс в URL всегда: `/ro/...`, `/ru/...`, `/en/...`; корень `/` → редирект по Accept-Language |
| Slug | **Один на все локали** (названия парфюма латиницей интернациональны). Локализуются контент и SEO-поля, не URL-пути товаров |
| Контент | Локализованные поля в Payload (title, description, seo); цены/SKU/остатки — общие |
| Валюта | MDL, формат вывода по локали |
| Заявки | Корзина (Zustand + localStorage) → форма → Telegram-бот + email (Resend). Оплаты нет |
| Хостинг | Hetzner CX22 (Falkenstein), Coolify, деплой из ветки `main` по push |
| CDN/DNS | Cloudflare (proxy включён), медиа — Cloudflare R2 |
| Аналитика | GA4; события view_item, add_to_cart, begin_checkout, generate_lead |
| Тесты | Чек-листы на каждом шаге + Playwright (4 сценария) + Lighthouse ≥ 90 mobile |

**Дизайн-трек (параллельный):** брендбук MON FLACON получен и разобран в `docs/BRAND.md` — палитра Deep Navy `#16293D` / Warm Cream `#E8CFB0`, типографика (веб-замена Helvetica Neue → Inter из-за лицензии, с кириллицей и румынскими диакритиками), правила логотипа, паттерн, фотостиль, голос бренда. **Нейтральной темы нет** — сайт брендовый с фазы 1 через токены. Ожидаются от владельца/дизайнера: структура сайта и вайрфреймы страниц + SVG-исходники лого и паттерна → фаза 6 становится композиционной интеграцией (распределение поверхностей, промо-блоки), а не рескином с нуля.

### 4.5.1 Денормализация скидки
**[CC]** Схему вариантов не менять — `oldPrice` у `variants[]` уже есть. Тот же хук `beforeChange` коллекции `products`, что считает `minPrice`/`maxPrice`/`inStock`, дополнительно считает по активным вариантам: `hasDiscount` (есть хоть один вариант с `oldPrice > price`) и `maxDiscountPercent` (округлённый максимум процента скидки среди них, 0 — если скидки нет). Оба поля — readonly в админке, индексированы.
**✔** Пересчитывается при сохранении товара · видно в админке как читаемые поля · есть индекс в БД на оба поля.

### 4.5.2 Бейдж скидки на карточке и странице товара
**[CC]** Эталонная карточка (WIREFRAMES.md §3) получает бейдж «−N%» в правом верхнем углу фото-зоны (отступ 9–12px) — заливка navy, текст cream, мелкий uppercase, трекинг ~0.14em (переменные токенов, без теней и рамки). Рядом с ценой — зачёркнутая старая цена.
**Вариант B (действующее правило — отменяет прежнюю формулировку «на карточке показывай максимальный процент среди активных вариантов», где бейдж и цена могли относиться к разным вариантам):** бейдж и цена карточки всегда описывают **один и тот же вариант**. Если уценённых вариантов нет — карточка ведёт себя как раньше: обычная минимальная цена, без бейджа и без зачёркивания. **Инвариант: бейдж без зачёркнутой цены рядом и зачёркнутая цена без бейджа — оба состояния невозможны.** Карточка едина для сайта → правило автоматически действует в каталоге, категории, поиске, «похожих». ## Приложение A — Чек-лист ручной приёмки

**Каталог:** ★ листинг открывается на ro/ru/en · фильтр по 2+ брендам корректен · range цены не пропускает товары мимо диапазона · счётчики фасетов честные · ★ ссылка с фильтрами воспроизводит состояние · сортировки не теряют товары · пагинация без дублей · пустая выдача фильтра — внятное состояние.
**Товар:** ★ переключение объёма меняет цену/SKU · объём без остатка недоступен · галерея и зум на тач · похожие релевантны и не содержат сам товар · перевод описания соответствует локали.
**Поиск:** латиница и кириллица находят одно и то же · опечатка в 1 букву не ломает выдачу · автодополнение закрывается по Esc/клику мимо.
**Корзина/заявка:** ★ добавление из листинга и из карточки · изменение количества пересчитывает итог · ★ корзина переживает перезагрузку · ★ заявка доходит в Telegram со всеми позициями и контактом · невалидный телефон блокируется с внятной ошибкой · повторный сабмит не создаёт дубль заказа.
**Акции:** бейдж скидки и зачёркнутая цена — только у товаров с `oldPrice > price`, процент верный · фильтр «со скидкой» и сортировка по скидке работают · промо-баннер и акционный hero появляются/пропадают строго по датам, ручное `enabled=false` их гасит независимо от дат.
**Локали:** ★ переключатель сохраняет текущую страницу · нет строк-заглушек и missing keys · форматы цены MDL корректны во всех трёх.
**Мобильный (реальный телефон):** ★ каталог+фильтры юзабельны на 360px · тап-таргеты ≥ 44px · нет горизонтального скролла · клавиатура не ломает форму заявки.
**Техника:** ★ 404 кастомная · console без errors на ключевых страницах · /admin недоступен менеджеру дальше его прав · ★ https без mixed content (прод).
**SEO:** hreflang присутствует · JSON-LD валиден · sitemap отдаёт 3 локали · страницы фильтров noindex.

## Приложение B — Требования к макетам (для дизайнера)

1. Figma с **токенами**: палитра (4–6 именованных цветов с hex), типографика — display + body (+ utility для цен/данных) с шкалой и весами, отступы, радиусы, тени.
2. Брейкпоинты: 360, 768, 1280 (1536 — опционально).
3. Экраны: главная, листинг с открытыми фильтрами (десктоп + мобильный bottom-sheet), карточка товара, корзина, форма заявки + «спасибо», страница бренда, статическая страница, 404.
4. Состояния компонентов: hover / focus / active / disabled / error / loading / empty (пустая корзина, пустой поиск).
5. Три локали: заголовки и кнопки проверить на длинных строках (RU и RO длиннее EN до ~30%) — ничего не должно ломаться.
6. Шрифты с поддержкой **latin + cyrillic** (обязательное требование — RU-локаль), лицензия для web.
7. Ассеты: иконки и лого в SVG; фото-стайлгайд для карточек товаров (фон, отступы, соотношение) — по нему клиент будет готовить 100+ фото.
8. Компонент карточки товара — отдельно и приоритетно: это 80% визуала сайта.
