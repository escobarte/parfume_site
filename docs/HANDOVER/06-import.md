# 06. Импорт каталога

- **Для кого:** разработчик, который поддерживает импорт; администратор, который регулярно обновляет цены и остатки из 1С.
- **Что здесь:** четыре формата CSV и как определяется формат; поведение колонок; что можно и чего нельзя очистить через CSV; ZIP с фото; словарь нот; логотипы брендов; экраны, эндпоинты, роли; сценарий регулярного обновления «Лёгким прайсом»; где продублирован список колонок.

Полный построчный справочник колонок — [`docs/CSV-IMPORT-RULES.md`](../CSV-IMPORT-RULES.md). Пошаговая инструкция — [`docs/import-guide.md`](../import-guide.md). Шаблоны — `docs/import-template*.csv`. Здесь — устройство и то, что важно знать разработчику.

## 1. Где запускается

| Способ | Что | Роль | Сбрасывает кэш витрины |
|---|---|---|---|
| `/admin/catalog-import`, блок «Шаг 1» | ZIP с фото → `POST /api/media-import` (`src/endpoints/adminMedia.ts`) | только admin | нет (не нужно) |
| `/admin/catalog-import`, блок «Шаг 2» | CSV товаров/прайса/переводов → `POST /api/catalog-import` (`src/endpoints/adminCatalog.ts`), переключатель «пробный режим», выбор «локали контента» | только admin | да, `revalidateAll()` после успешного боевого прогона |
| `/admin/catalog-import`, кнопка «Сбросить кэш витрины» | `POST /api/catalog-revalidate` | только admin | да, это и есть сброс |
| `/admin/notes-import` | словарь нот: ZIP иконок (тот же `/api/media-import`) + CSV → `POST /api/notes-import` (`src/endpoints/adminNotes.ts`) | только admin | поштучно, хуками коллекции `notes` |
| CLI | `pnpm run import <файл.csv> [--dry-run] [--locale=ro\|ru\|en]` (`scripts/import.ts`); в прод-контейнере — `./node_modules/.bin/tsx scripts/import.ts <файл>` | доступ к терминалу | **нет** — после CLI нужен ручной сброс |

Экраны — кастомные views Payload (`src/components/admin/ImportView.tsx`, `NotesImportView.tsx`), обёрнуты в `DefaultTemplate` вручную; доступ проверяется внутри компонента и ещё раз в эндпоинте (`isAdmin` → иначе 403). Пункты меню (`ImportNavLink.tsx`, `NotesImportNavLink.tsx`) менеджеру не показываются.

`pnpm import` (без `run`) — встроенная команда pnpm, которая может снести `pnpm-lock.yaml`. Использовать `pnpm run import` или `pnpm import:csv`.

Лимиты: CSV и CSV нот — 10 МБ; ZIP — 200 МБ, файл внутри — 8 МБ. ZIP больше ~100 МБ упирается в лимит размера запроса Cloudflare Free — архив делить на части.

## 2. Движок товарного CSV — `src/lib/import/`

| Файл | Роль |
|---|---|
| `csv.ts` | `toTable()` — разбор CSV; **каждая ячейка обрезается по краям**, отсутствующая/пустая ячейка = `''` (не `undefined`) |
| `detect.ts` | определение формата по заголовку (`detectKind`), какие `description_*` есть в файле, подписи форматов `KIND_LABELS` |
| `schema.ts` | zod-схемы строк каждого формата |
| `validate.ts` | построчная валидация, поиск дублей |
| `engine.ts` | `runImport()`: разбор → валидация **всего** файла → применение **в одной транзакции** (`beginTransaction`/`commit`/`rollback`); в пробном режиме транзакция не открывается и ничего не пишется |
| `applyProducts.ts` | форматы A/B: группировка, upsert по `handle`, слияние вариантов по `sku`, описания по локалям, фото, автосоздание справочников |
| `applyUpdates.ts` | «Лёгкий прайс» и переводы |
| `productScalars.ts`, `relations.ts`, `images.ts`, `brandLogos.ts` | разбор значений, связи, поиск файлов в медиатеке по имени, логотипы брендов |
| `report.ts`, `payloadErrors.ts` | текстовый отчёт (одинаков для админки и CLI), понятные сообщения из ошибок Payload |

### 2.1. Определение формата (`detectKind`, порядок важен)

| Если в заголовке есть | Формат |
|---|---|
| `handle` и `locale` | переводы |
| `handle` и `variants` | товары, формат B (варианты JSON-колонкой) |
| `handle`, `sku`, `price` | товары, формат A (строка = вариант) |
| `sku` и (`price` или `stock`) | «Лёгкий прайс» |
| иначе | ошибка «не удалось определить формат» |

### 2.2. Колонки (по `schema.ts`)

- **Общие для A и B:** `handle`*, `title`*, `brand`* (slug бренда), `slug`, `brand_logo`, `country_of_origin`, `product_category`, `categories`, `notes`, `notes_top`, `notes_heart`, `notes_base`, `gender`, `family_ro/ru/en`, `images`, `description`, `description_ro/ru/en`, `is_new`, `is_hit`.
- **Формат A, вариант:** `volume`*, `sku`*, `price`*, `old_price`, `stock`, `is_active`, `variant_image`.
- **Формат B:** `variants`* — JSON-массив `{ volume, sku, price, oldPrice?, stock?, isActive?, image? }`.
- **Лёгкий прайс:** `sku`*, `price`, `stock`.
- **Переводы:** `handle`*, `locale`* (`ro`/`ru`/`en`), `description`. Название товара здесь не переводится — оно одно на все языки.

(* — обязательна.) Списки через `|` или запятую. Булевы «да»: `1`, `true`, `yes`, `да`, `y`, `x`. Числа: пробелы внутри снимаются, десятичная запятая допустима, отрицательное — ошибка.

### 2.3. Главный принцип: пустая ячейка = «не трогать»

Пустая ячейка означает «здесь не сказано», а не «сказано, что пусто». Отсюда:

| Можно изменить через CSV | Нельзя очистить через CSV (только в админке) |
|---|---|
| любое значение, вписав новое | зачёркнутую цену `old_price` (снять уценку) |
| список фото — непустая `images` заменяет галерею целиком (если ни одно имя не найдено — галерея станет **пустой**) | фото варианта, логотип бренда |
| категории/ноты/пирамиду — непустая ячейка заменяет список целиком | `family`, описание (пустая ячейка не стирает) |
| остаток и видимость варианта (`stock`, `is_active`) | удалить товар, вариант, категорию, ноту — CSV ничего не удаляет; вариант можно скрыть `is_active` |

Значения по умолчанию (`stock = 0`, `isActive = true`, `productCategory = perfume`, `countryOfOrigin = europe`) получает **только вновь создаваемая** запись. Дефолт, подставленный при слиянии с существующей, затирал бы базу: значение по умолчанию принадлежит только созданию записи.

В формате A поля уровня товара собираются из нескольких строк одного `handle`: берётся **первая заполненная** строка (`adoptFilledCells` в `applyProducts.ts`), а не первая строка вообще.

Описания: если в заголовке есть хоть одна `description_ro/ru/en`, одиночная `description` игнорируется целиком; каждая непустая языковая ячейка пишется в свою локаль. Одиночная `description` пишется только в те локали, где описание пустое (готовые переводы не затираются) — и проверять пустоту приходится **до** основного `update`, потому что Payload с `fallback: true` сам проливает `ro` в пустые локали.

Реакция на неверные значения различается: неверный `gender`/`locale`/отрицательное число/дубль `sku` или `handle` — **весь файл отклоняется**; неверный `volume` — пропускается вариант; неверные `product_category`/`country_of_origin` — предупреждение, поле не меняется; ненайденный файл фото — предупреждение.

Сопоставление: товар — по `handle`; вариант внутри товара — по `sku` (варианты, которых нет в файле, остаются); «Лёгкий прайс» — по `sku` варианта во всём каталоге, новых товаров не создаёт. Новый товар создаётся сразу **опубликованным**. Slug существующего товара меняется только при явной колонке `slug`. Неизвестные бренды, категории и ноты **создаются автоматически** (ноты — с `needsReview: true`) — в отчёте их список; это главный способ поймать опечатку в slug.

Правило скидки «на все активные варианты или ни на один» действует и при импорте: нарушение на любом товаре откатывает весь файл.

## 3. Фото — ZIP, затем CSV

1. ZIP загружается на «Шаг 1» (`/api/media-import`). Архив распаковывается **в памяти** (`adm-zip`, чистый JS), каждый файл создаётся в Media через `payload.create({ file: Buffer })` без записи временных файлов. Файл с таким же именем, который уже есть в медиатеке, **не перезаписывается** — переиспользуется (отчёт «reused»). `alt` генерируется из имени файла, локаль `ro`.
2. CSV ссылается на файлы по **точному имени** (регистр и расширение важны): `images`, `variant_image`, `brand_logo`.

Импортёр ничего не скачивает по URL. Рекомендация (`docs/import-guide.md`): квадрат не меньше 1200×1200, до 1 МБ.

## 4. Словарь нот — `/admin/notes-import`

Отдельный экран, не смешан с товарами. Шаг 1 — ZIP иконок через тот же `/api/media-import`. Шаг 2 — CSV с колонками `slug`* , `title`, `group`, `image` (`src/lib/import/applyNotes.ts`). Старые колонки `name_ro/name_ru/name_en` дают явную ошибку формата. В отличие от товаров — **построчная терпимость**: ошибка в одной строке не блокирует остальные. Создание/обновление по slug.

---

## 5. Логотипы брендов

Колонка `brand_logo` в товарном CSV пишет логотип не в товар, а в запись бренда, один раз за прогон (`brandLogos.ts`); при разных именах в строках одного бренда берётся первое. Логотип виден на `/brands` и в OG-превью страниц брендов.

## 6. Регулярное обновление из 1С — «Лёгкий прайс»

Сценарий:

1. В 1С выгрузить отчёт, где в одной таблице есть артикул, цена и остаток.
2. Переименовать колонки в `sku`, `price`, `stock` (достаточно `sku` и одной из двух). Артикулы должны совпадать с `sku` вариантов на сайте.
3. Сохранить как CSV. Разделитель (`,`, `;` или табуляция) определяется автоматически по первой строке (`detectDelimiter` в `src/lib/import/csv.ts`), BOM снимается — подходит обычное «Сохранить как CSV» из Excel.
4. `/admin/catalog-import` → «Шаг 2» → выбрать файл → **пробный режим** → прочитать отчёт: сколько вариантов затронуто, какие `sku` не найдены.
5. Снять пробный режим → загрузить ещё раз. Кэш витрины сбросится автоматически.
6. Выборочно проверить пару товаров на сайте в окне инкогнито.

Что «Лёгкий прайс» **не** делает: не создаёт товары, не трогает зачёркнутую цену, не включает/выключает варианты, не меняет ничего, кроме `price` и `stock`.

> **Важно.** Если у товара со скидкой новая `price` станет ≥ `oldPrice` лишь на части вариантов, правило скидки отклонит весь файл — смотреть отчёт.

Автоматического обмена с 1С нет: только ручная загрузка файла. Обратное направление (заказы → 1С) — CSV-файлы по SFTP, см. [04-order-flow.md](04-order-flow.md).

## 7. Список колонок продублирован — при любом изменении грепать

Единого источника истины нет. При добавлении/переименовании колонки проверить все места:

1. `src/lib/import/schema.ts` — сама схема;
2. `src/lib/import/detect.ts` — `KIND_LABELS`;
3. `src/lib/import/report.ts` — шапка и разделы отчёта; счётчики в `ImportPlan` (`types.ts`);
4. `scripts/import.ts` — текст `USAGE` (template literal: обратные кавычки внутри ломают строку);
5. `src/components/admin/ImportForm.tsx` — подсказка под выбором локали;
6. `docs/import-guide.md`, `docs/CSV-IMPORT-RULES.md`, шаблоны `docs/import-template*.csv`;
7. для колонок со списком значений — сам список в `src/lib/catalog/*.ts` (не в коллекции: импортёр не тянет конфиг коллекции).

Приём: `grep -rn 'description_ro'` (или имя меняемой колонки) по всему репозиторию.
