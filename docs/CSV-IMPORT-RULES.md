# CSV-импорт товаров — справочник правил

> Справочник по **правилам** заполнения файлов: что обязательно, что происходит с каждой
> колонкой при повторном импорте, какие значения допустимы буквально.
> Пошаговая инструкция «как залить» — отдельный документ, `docs/import-guide.md`.
>
> Все значения ниже выписаны из кода (`src/lib/import/`, `src/lib/catalog/`,
> `src/collections/Products.ts`), а не из переписки. Сверено 2026-09-18.

---

## 1. Четыре формата файла

Формат определяется **по заголовку файла автоматически** (`src/lib/import/detect.ts`),
настройкой импорта его не переопределить. Проверки идут строго в этом порядке — первая
совпавшая выигрывает:

| № | Формат | Распознаётся, если в заголовке есть | Что делает |
|---|---|---|---|
| 1 | **Переводы** | `handle` + `locale` | пишет описание в одну указанную локаль |
| 2 | **Товары B** | `handle` + `variants` | товар целиком одной строкой, варианты — JSON |
| 3 | **Товары A** | `handle` + `sku` + `price` | строка = один вариант товара |
| 4 | **Лёгкий прайс** | `sku` + (`price` или `stock`), без `handle` | меняет только цену и остаток |

Если не подошло ни одно сочетание — **файл отклоняется целиком**, в базу ничего не пишется:

```
не удалось определить формат файла по заголовку — ожидались колонки
handle+sku+price (A), handle+variants (B), sku+price/stock (прайс)
или handle+locale (переводы)
```

Порядок важен на практике: файл с `handle,locale,description` — это **переводы**, даже если
в нём есть и другие колонки; файл с `handle,sku,price` — это **формат A**, а не лёгкий прайс.

### Разделитель, кодировка, заголовки

- Разделитель определяется по первой строке: `,`, `;` или табуляция (Excel в русской и
  румынской локали сохраняет с `;`).
- BOM и CRLF снимаются автоматически, кавычки и переводы строк внутри поля поддерживаются
  по RFC 4180 (`""` — экранированная кавычка).
- Заголовки приводятся к нижнему регистру и `snake_case`: `Old Price` → `old_price`.
- **У каждой ячейки срезаются пробелы по краям** — это важно для «строгих» значений:
  ` kids ` пройдёт как `kids`, а `Kids` — нет.
- Пустые строки в конце файла игнорируются. Файл без строк данных отклоняется.

### Формат A — строка = вариант

Обязательные колонки: `handle`, `title`, `brand`, `volume`, `sku`, `price`.

```csv
handle,title,brand,volume,sku,price,old_price,stock,is_active,gender,product_category,country_of_origin
MO-WOOD,Signature Wood,maison-orphee,5ml,MO-SW-05,200,250,12,1,unisex,perfume,europe
MO-WOOD,Signature Wood,maison-orphee,Full Size,MO-SW-FS,980,,4,1,unisex,perfume,europe
```

Две строки с одним `handle` — это один товар с двумя вариантами. Поля уровня товара
(`title`, `gender`, `product_category`, `country_of_origin`, `images`, описания…) берутся
из **первой ЗАПОЛНЕННОЙ строки** этого `handle`: пустая ячейка значит «в этой строке не
сказано» и не перебивает значение, стоящее строкой ниже (исправлено 2026-09-22 — до этого
раздел или пол, проставленные не в верхней строке товара, молча пропадали). Непустую
ячейку строка ниже не перетирает — приоритет у первой заполненной.

### Формат B — варианты JSON-колонкой

Обязательные колонки: `handle`, `title`, `brand`, `variants`.

```csv
handle,title,brand,variants
MO-WOOD,Signature Wood,maison-orphee,"[{""volume"":""5ml"",""sku"":""MO-SW-05"",""price"":200,""stock"":12}]"
```

Внутри каждого элемента массива обязательны `volume`, `sku`, `price`; необязательны
`oldPrice`, `stock`, `isActive`, `image`. Возможности форматов A и B совпадают.

### Лёгкий прайс — только цена и остаток

Обязательная колонка: `sku`. Плюс в заголовке нужна хотя бы одна из `price` / `stock`.

```csv
sku,price,stock
MO-SW-05,220,9
MO-SW-FS,1010,3
```

Ничего, кроме цены и остатка конкретного варианта, не трогает. Товары этим форматом
**не создаются**; неизвестный `sku` — строка пропускается с пометкой в отчёте.

### Переводы — описание в одну локаль

Обязательные колонки: `handle`, `locale`. Описание — в колонке `description`.

```csv
handle,locale,description
MO-WOOD,ro,Lemn cald și bergamotă limpede.
MO-WOOD,ru,Тёплое дерево и прозрачный бергамот.
MO-WOOD,en,Warm wood and clear bergamot.
```

Название товара здесь не переводится: `title` — одно значение на все языки.
Строка без `description` пропускается с пометкой.

## 2. Полный список колонок

### 2.1. Поля уровня товара (форматы A и B)

| Колонка | Обязательна | Колонки нет / ячейка пустая | Ячейка заполнена |
|---|---|---|---|
| `handle` | **да** (A, B) | — | ключ поиска товара, не меняется |
| `title` | **да** (A, B) | — | заменяет название (одно на все языки) |
| `brand` | **да** (A, B) | — | slug бренда; нет такого — **бренд создаётся автоматически** |
| `slug` | нет | адрес товара не меняется | заменяет адрес (значение прогоняется через slugify) |
| `brand_logo` | нет | логотип бренда не трогается | имя файла из медиатеки → пишется в запись **бренда**, один раз за прогон |
| `categories` | нет | список не трогается | **заменяет список целиком**; неизвестные slug создаются автоматически |
| `notes` | нет | не трогается | **заменяет целиком**; неизвестные ноты создаются с пометкой «на вычитку» |
| `notes_top`, `notes_heart`, `notes_base` | нет | пирамида не трогается | **заменяет пирамиду целиком** (записывается, если заполнена хоть одна из трёх) |
| `gender` | нет | не трогается | заменяет. Значение вне списка — **весь файл отклоняется** |
| `product_category` | нет | не трогается (у нового товара — `perfume`) | заменяет. Значение вне списка — предупреждение, поле не меняется |
| `country_of_origin` | нет | не трогается (у нового товара — `europe`) | заменяет. Значение вне списка — предупреждение, поле не меняется |
| `family_ro`, `family_ru`, `family_en` | нет | эта локаль не трогается | заменяет семейство в своей локали |
| `description` | нет | не трогается | пишется **только в те локали, где описание пустое** — готовые переводы не затирает |
| `description_ro`, `description_ru`, `description_en` | нет | эта локаль не трогается | заменяет описание своей локали. Если заполнена хоть одна из трёх — одиночная `description` **игнорируется целиком** |
| `images` | нет | фото не трогаются | **заменяет галерею целиком**; имена через `\|` или запятую, первое — обложка |
| `is_new`, `is_hit` | нет | не трогается | заменяет флаг |

### 2.2. Поля уровня варианта

Формат A — колонки строки; формат B — ключи внутри JSON (`oldPrice`, `isActive`, `image`).

| Колонка (A) | Ключ (B) | Обязательна | Колонки нет / ячейка пустая | Ячейка заполнена |
|---|---|---|---|---|
| `volume` | `volume` | **да** | — | значение из списка объёмов; вне списка — **вариант пропускается** с предупреждением, файл грузится дальше |
| `sku` | `sku` | **да** | — | ключ сопоставления варианта |
| `price` | `price` | **да** | — | заменяет цену |
| `old_price` | `oldPrice` | нет | зачёркнутая цена **сохраняется** | заменяет |
| `stock` | `stock` | нет | остаток **сохраняется**; у нового варианта — `0` | заменяет |
| `is_active` | `isActive` | нет | признак показа **сохраняется**; у нового варианта — включён | заменяет |
| `variant_image` | `image` | нет | фото варианта сохраняется | имя файла из медиатеки; не найдено — предупреждение, фото не меняется |

> **Важно про `stock` и `is_active`.** До 2026-09-18 пустая ячейка обнуляла остаток и
> включала выключенный вариант — это починено (`[2026-09-18]` в CHANGELOG). Сейчас правило
> общее для всех «щадящих» колонок: **нет значения — значит «не трогать»**, а значения по
> умолчанию получает только вновь создаваемый вариант.

### 2.3. Колонки лёгкого прайса и переводов

| Колонка | Формат | Обязательна | Пустая | Заполнена |
|---|---|---|---|---|
| `sku` | прайс | **да** | — | ключ поиска варианта |
| `price` | прайс | нет* | цена не меняется | заменяет |
| `stock` | прайс | нет* | остаток не меняется | заменяет |
| `handle` | переводы | **да** | — | ключ поиска товара |
| `locale` | переводы | **да** | — | язык, в который пишется описание |
| `description` | переводы | нет | строка пропускается | заменяет описание этой локали |

\* Хотя бы одна из `price` / `stock` должна быть **в заголовке**, иначе файл не опознается
как прайс.

## 3. Поля с ограниченным набором значений

Шесть мест, где значение выбирается из списка, а не пишется свободно. Поведение при
неверном значении **у каждого своё** — это не единое правило.

### `volume` / `variants[].volume` — 5 значений

```
3ml   5ml   10ml   Travel Size   Full Size
```

- **Регистр важен**, пробелы внутри значения тоже (`Full Size`, не `full size`).
- Неверное значение: **вариант пропускается**, предупреждение в отчёт, остальной файл
  грузится. Если у товара невалидны все строки и товара ещё нет в базе — товар не создаётся.
- Похожее написание распознаётся отдельно: «`full size` отличается от `Full Size` только
  регистром или пробелами — вероятно опечатка».

### `gender` — 4 значения

```
female   male   unisex   kids
```

- **Регистр важен.** `Kids`, `KIDS`, `Female` не принимаются.
- Неверное значение: **весь файл отклоняется**, ничего не записывается
  (`gender: допустимо female / male / unisex / kids`).
- Пробелы по краям ячейки не мешают — их снимает разбор CSV.

### `product_category` — 3 значения

```
perfume   bodyCare   lipBalm
```

- **Регистр не важен**: `bodycare`, `BODYCARE`, ` LipBalm ` приводятся к канону.
- Русские подписи («Парфюмерия», «Уход за телом», «Бальзам для губ») **не принимаются**.
- Неверное значение: предупреждение в отчёт, **поле не меняется**, товар импортируется.
- В формате A строк на товар несколько: канон — первая **заполненная** строка `handle`
  (пустые ячейки пропускаются), расхождение двух непустых внутри одного товара уходит
  предупреждением («взято первое заполненное»).

### `country_of_origin` — 3 значения

```
uae   europe   usa
```

- **Регистр не важен**. Русские подписи («ОАЭ», «Европа», «США») не принимаются.
- Неверное значение: предупреждение, поле не меняется.
- Правило первой заполненной строки `handle` — как у `product_category`.

### `locale` (формат переводов) — 3 значения

```
ro   ru   en
```

- **Регистр важен.** Неверное значение: **весь файл отклоняется**
  (`locale: допустимо ro / ru / en`).

### Логические колонки `is_active`, `is_new`, `is_hit` — 6 слов «да»

```
1   true   yes   да   y   x
```

- Регистр не важен, пробелы по краям снимаются.
- Любое другое непустое значение (`0`, `no`, `нет`, `false`) читается как «нет».
- Пустая ячейка — не «нет», а «не трогать».

### Фиксированные имена колонок с языком

`description_ro` / `description_ru` / `description_en` и `family_ro` / `family_ru` /
`family_en` — суффикс только из набора `ro`, `ru`, `en`. Колонка с другим суффиксом просто
игнорируется (она не входит ни в одну схему).

### Числовые колонки — не enum, но со своими правилами

`price`, `old_price`, `stock` (и `price`/`oldPrice`/`stock` в JSON формата B):

- пробелы внутри числа снимаются, **десятичная запятая допускается** (`1 200,50` → `1200.5`);
- **отрицательное значение — ошибка формата, файл отклоняется целиком**;
- `0` — валидное значение и не считается пустой ячейкой.

## 4. Матчинг и повторный импорт

| Формат | По чему ищется | Нашлось | Не нашлось |
|---|---|---|---|
| Товары A / B | по `handle` товара (поле уникально и индексировано) | **обновление** существующей записи | создаётся новый товар, сразу опубликованный |
| Лёгкий прайс | по `sku` варианта | обновляется цена/остаток этого варианта | строка пропускается, товар **не** создаётся |
| Переводы | по `handle` товара | пишется описание в указанную локаль | строка пропускается |

Внутри товара **варианты сопоставляются по `sku`**: совпал — обновляется, не совпал —
добавляется новым. **Варианты, которых нет в файле, остаются нетронутыми** — прайс с одним
объёмом не удаляет остальные.

Дубли внутри одного файла — ошибка формата, файл отклоняется целиком:
дважды один `sku` (формат A и прайс) или дважды один `handle` (формат B).

Адрес товара (`slug`) при повторном импорте **не перезаписывается**, если колонки `slug`
нет в файле: иначе переименование в прайсе молча ломало бы ссылки и канониклы. У нового
товара slug собирается из названия.

### Всё или ничего

Импорт идёт одной транзакцией. Любая ошибка формата (или отказ базы на конкретном товаре)
откатывает **весь файл**. Предупреждения — не ошибки: неизвестный объём, ненайденное фото,
значение вне списка у `product_category`/`country_of_origin` файл не роняют.

Перед боевым прогоном доступен **пробный режим** (dry-run): отчёт считается честно, в базу
ничего не пишется.

### Что создаётся автоматически

| Справочник | Когда | Что получает |
|---|---|---|
| Бренд | `brand` указан, записи нет | slug + название из slug |
| Категория | slug в `categories`, записи нет | slug + название из slug |
| Нота | slug в `notes` / `notes_*`, записи нет | slug + название из slug + пометка «на вычитку» |

Все автосозданные записи перечисляются в отчёте — это главный способ поймать опечатку в
slug (`maison-orphe` вместо `maison-orphee` создаст второй бренд, а не свяжет с прежним).
Slug нормализуется: кириллица транслитерируется, диакритика снимается, регистр опускается.

### Фото

Импортёр **ничего не скачивает**. Имена в `images`, `variant_image`, `brand_logo` ищутся
среди уже загруженных файлов медиатеки по **точному имени файла, включая регистр и
расширение** (`Alpha-1.JPG` ≠ `alpha-1.jpg`). Фото загружаются заранее ZIP-архивом на
экране импорта в админке.

Ненайденное имя — предупреждение, а не ошибка. Но у `images` есть особенность: непустая
ячейка означает «этот список — истина», поэтому если **ни одно** имя не нашлось, галерея
станет пустой.

### Ограничения по размеру

| Что | Предел |
|---|---|
| CSV-файл | 10 МБ |
| ZIP-архив с фото | 200 МБ |
| Один файл внутри архива | 8 МБ |

## 5. Известные ограничения

1. **Файл «только описания» невозможен.** Заголовок `handle,description_ro,description_ru,description_en`
   не подходит ни под один формат — файл отклоняется целиком. Дозаливать описания нужно
   форматом переводов (`handle,locale,description`, по строке на язык) либо форматом A,
   повторив обязательные колонки.
2. **Форматы A и B требуют `title`, `brand`, `volume`, `sku`, `price` в каждой строке**,
   даже если значения не меняются. Файл, где заполнены только `handle`, `sku` и `price`,
   будет отклонён — для обновления одних цен есть лёгкий прайс.
3. **Лёгкий прайс не умеет `old_price`.** Поставить или изменить зачёркнутую цену можно
   только форматом A/B. Снять уценку через CSV нельзя вовсе — только вручную в админке
   (пустая ячейка означает «не трогать»).
4. **Правило уценки может отклонить файл.** Скидка допустима либо на всех активных
   вариантах товара сразу, либо ни на одном. Если новая цена окажется выше сохранённой
   `old_price` только у части вариантов — или если к товару со скидкой добавится активный
   вариант без неё — импорт откатится целиком с указанием SKU и причины.
5. **Удалять нечем.** CSV не умеет удалять товары, варианты, ноты или категории: лишний
   вариант, однажды заведённый, снимается только в админке (или отключается через `is_active`).
6. **Пол `kids` есть в импорте**, но детский товар попадает в раздел «Kids» по полю
   `gender`, а не по `product_category` — эти две колонки независимы.
7. **Лимит одной строки — один товар одного бренда.** Колонка `brand_logo` пишет не в
   товар, а в запись бренда; при разных именах файла в строках одного бренда берётся
   первое, остальное уходит предупреждением.

## 6. Что показывает отчёт

Отчёт одинаков для админки и командной строки:

- шапка: распознанный формат, локаль контента, режим (пробный или боевой);
- при ошибке — список с номерами строк файла (как в Excel, 1 — заголовок) и полем;
- при успехе — сколько товаров создано и обновлено, сколько вариантов создано и обновлено;
- разделы предупреждений: объём не из списка, фото не найдены, фото вариантов не найдены,
  логотипы брендов, значения `country_of_origin` и `product_category` вне списка и
  расхождения внутри одного `handle`, автосозданные справочники, пропущенные строки.

Разделы печатаются, только если соответствующие колонки в файле участвовали — молчание в
отчёте означает «в файле этого не было».
