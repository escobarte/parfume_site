# CLAUDE.md — правила работы по проекту

Ты — исполнитель. Спецификация — `docs/PLAN.md`, последовательность работ — `docs/PROMPTS.md`, журнал — `docs/CHANGELOG.md`. Каждую сессию начинай с чтения этих трёх файлов. Принцип: **максимум автоматизации** — всё, что можешь сделать и проверить сам, делаешь и проверяешь сам, не спрашивая. Владельцу оставляешь только то, что физически недоступно тебе.

## Запрещено (без исключений)

1. **Git.** Никогда не выполняй `git`/`gh` и ничего не меняй в `.git/`. Вместо этого печатай git-блок (см. ритуал). Все git-операции выполняет владелец вставкой твоего блока.
2. **SSH и удалённые машины.** `ssh`, `scp`, `rsync` — запрещены. Серверные действия оформляй скриптами + командой запуска для владельца.
   <!-- OPT-IN: чтобы разрешить ssh на прод-сервер, владелец раскомментирует строку ниже -->
   <!-- РАЗРЕШЕНО: ssh deploy@<IP_СЕРВЕРА> для выполнения подготовленных скриптов -->
3. **Прод-секреты.** Значения боевых токенов/ключей не запрашивай в чат и не выводи в логи/файлы. Прод-env владелец вносит в панели Coolify по твоему списку.
4. **Деструктив** (drop таблиц, удаление media, `rm -rf` вне tmp) — только после явного «да».

## Разрешено и ожидается (делай сам, не спрашивая)

- **Локальный `.env`**: создавай и правь. Локальные секреты генерируй сам (`openssl rand -hex 32`). Для внешних сервисов ставь плейсхолдер `CHANGEME_*` и в конце шага перечисли владельцу, что заполнить. Значения секретов в чат не выводи.
- **Зависимости из стека плана** — ставь без согласования, фиксируй в changelog (пакет + зачем). Вне стека / экзотика — спроси одним вопросом с вариантами.
- **Самопроверка**: всё, что проверяется командой, проверяй сам — dev-сервер, `curl` к localhost, `pnpm tsc --noEmit`, тесты, сборка Docker-образа, скриншоты через Playwright. После деплоя разрешены read-only `curl`/GET к прод-домену для smoke-проверок.
- **`sudo apt` внутри WSL** — для системных зависимостей (Playwright deps и т.п.).
- **Файлы Windows-стороны** через `/mnt/c/...` — можно писать (например `.wslconfig`), предупредив, что для применения нужен `wsl --shutdown` от владельца.

## Ритуал завершения каждого шага (обязателен, порядок фиксирован)

1. **Резюме** — что сделано, какие файлы, 3–6 строк.
2. **Отчёт самопроверки** — таблица: проверка → команда → ✔/✘. Все ✘ чини до завершения шага. Владельцу оставляй только 👁-пункты (визуал, телефон, внешние сервисы) — максимум 1–3, а лучше 0.
3. **Changelog** — допиши запись в `docs/CHANGELOG.md` (формат ниже). Это не опция: шаг без записи в changelog не считается выполненным.
4. **⎇ Git-блок** — печатай одним куском для копипаста:
   ```
   git add <файлы> && git commit -m "feat(scope): сообщение"
   git add <файлы> && git commit -m "..."
   git push
   ```
   Внутри фазы накапливай атомарные коммиты и выдавай один блок в конце фазы (несколько commit-строк + push). Сообщения — Conventional Commits, описание по-русски.

## docs/CHANGELOG.md — формат

Новые записи сверху:
```
## [ГГГГ-ММ-ДД] Фаза N.M — название шага
- Сделано: ...
- Файлы: ключевые созданные/изменённые
- Зависимости: добавленные пакеты (если были)
- Ждёт владельца: git-блок / CHANGEME_* / 👁-проверки (если есть)
- Заметки: грабли, решения, отложенное
```
Changelog — твоя память между сессиями. Новая сессия = чтение changelog → продолжение с первого незакрытого пункта.

## Технологический каркас (не менять без запроса)

- Next.js 15 App Router + Payload CMS 3 в одном приложении; данные через **Local API**, не HTTP.
- TypeScript strict; только `pnpm`; Node 22.
- Tailwind v4 + shadcn/ui; все цвета/радиусы/шрифты — через токены `src/styles/tokens.css`, хардкод значений в компонентах запрещён.
- **Дизайн — строго по `docs/BRAND.md`** (MON FLACON): палитра navy/cream, Inter, uppercase-заголовки с трекингом, линии вместо теней, воздух. Фирменные EN-фразы бренда не переводятся ни в одной локали.
- Локали `ro` (дефолт), `ru`, `en` через next-intl, префикс всегда, один slug на все локали. Новая UI-строка — сразу во все три `messages/*.json`; машинный перевод помечай `TODO review`.
- PostgreSQL; фильтры — nuqs (состояние в URL); корзина — Zustand persist; валидация — Zod.
- Цены только MDL. `minPrice/maxPrice/inStock` — только хуками, руками не пишутся.
- Server Components по умолчанию; `'use client'` точечно.
- После изменения схемы Payload: `payload generate:types` + `pnpm tsc --noEmit`.

## Конвенции

- Код и идентификаторы — англ.; комментарии, коммиты, ответы, changelog — рус.
- Файлы > 300 строк разбивай. Бизнес-логика в `src/lib/`, компоненты тупые.
- Ошибки пользователю — через messages на языке локали, не хардкодом.
- Отвечай кратко. Большие листинги — в файлы, не в чат. Конфликт требований — остановись и задай один вопрос с вариантами.
