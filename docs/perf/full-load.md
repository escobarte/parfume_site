# Нагрузочный smoke — фаза 8.3

Прод-сборка (`pnpm build && pnpm start`, `output: standalone`-предупреждение ожидаемо, см. `docs/GOTCHAS.md`), отдельный порт `3100`, чтобы не мешать dev-серверу (`3000`) с E2E-тестами. Замер — `curl -w '%{time_total}'` (server-side TTFB+рендер, без сети/браузера) и Playwright для админки.

## Объём

Демо-каталог фазы 2 (12 товаров) + синтетические `load-001…load-120` (`pnpm seed:load`, скрипт `scripts/seed-load.ts`): **132 товара, 755 вариантов** (SKU). Одна общая плейсхолдер-картинка на все синтетические товары — цель прогона -- нагрузить БД/листинг/фильтры, а не генератор изображений.

## Находка: `PAGE_SIZE=24` меняет смысл «фильтр сузил выдачу» на масштабе

Старый самопроверочный скрипт `scripts/check-catalog.mjs` (фаза 3) проверяет фильтрацию через дельту **видимого числа карточек** на странице (`totalAll` → `filtered`). Пока каталог помещался на одну страницу (12 демо-товаров < `PAGE_SIZE=24`), это было прямым мерилом: фильтр всегда уменьшал число карточек. При 132 товарах это перестаёт быть надёжным: у каждого из трёх демо-брендов теперь ~44 товара — фильтр по бренду **реально** сужает выдачу (132 → 44, подтверждено через `/api/products?...&limit=0` → `totalDocs`), но первая страница фильтрованной выдачи всё равно рисует **24** карточки — ровно столько же, сколько и на первой странице без фильтра. Видимая дельта — 0, хотя фильтрация работает корректно.

Из-за этого `check-catalog.mjs` и (изначально) `tests/e2e/catalog-filters.e2e.spec.ts` на этом объёме таймаутились на `waitForFunction(count changed)`. Новые формальные тесты (`tests/e2e/catalog-filters.e2e.spec.ts`) написаны и провалидированы **до** генерации нагрузочных данных и проверяют фильтр через прямой API-запрос `totalDocs`, не сравнение видимых карточек — это не задевает их. Старый ad-hoc-скрипт фазы 3 никто не переписывал (не входит в объём фазы 8 — он покрывает функциональность фазы 3, а не формальный тестовый набор), но факт стоит знать: на реальном прайсе (~100+ товаров) любая проверка «фильтр уменьшает число карточек» должна сравнивать `totalDocs`, а не количество `<article>` на странице.

Функционально фильтрация проверена напрямую через REST (`totalDocs`) и через `flags=isHit` (20 из 132, дельта видна и на карточках) — работает корректно на всём объёме.

## Как воспроизвести и откатить

```bash
pnpm seed:load                 # добавить 120 синтетических товаров (идемпотентно — upsert по slug load-NNN)
LOAD_COUNT=300 pnpm seed:load   # другой объём, если нужно
```

Откат — синтетические товары удалены после снятия замеров этой сессией (см. `docs/CHANGELOG.md`), каталог возвращён к 12 демо-товарам фазы 2. Если понадобится повторить прогон позже — `pnpm seed:load` снова насеет `load-001…load-120`, удалить можно через `/admin/collections/products` (фильтр по `slug` `contains` `load-`) либо API-запросом `DELETE /api/products?where[slug][like]=load-`.
